## Security

- **C181 · minor · S** — no Content-Security-Policy, so any XSS through upstream text runs uncontained; the other headers come from the live proxy ([architecture.md](architecture.md#build-and-serving)). Set a strict CSP (`script-src 'self'`, Steam CDN images) in `server.js`, checking what inline styles, the Steam/ITAD images and the HLS video hosts need.
- **C182 · minor · S** — `GET /api/me` (`server.js:1249`) has no rate limit and `getSessionUser` parses the account's whole prefs (up to `PREFS_MAX_BYTES`) on every call: a signed-in client hammering it blocks the event loop. Put it behind a limiter; have auth read only the session row and load prefs only where returned.
- **C293 · minor · S** — another site can sign a visitor out: a cross-site form `POST /auth/logout` carries no `sid` (SameSite=Lax), but its response's `Set-Cookie` still clears it. Reject `Sec-Fetch-Site: cross-site` (or a foreign `Origin`).
- **C295 · minor · S** — `GET /api/metrics` publicly shows live budget use (`hourTopClient`) and open breakers, telling an abuser when to push; observability.md calls it nothing sensitive. Put the budget and breaker detail behind a token, keep `/api/health` public.
- **C296 · minor · S** — link previews' absolute `og:image` (`sendAppShell`) and `/opensearch.xml` still build the origin from the `Host` header; escaped, so it only matters behind a shared cache. Use `PUBLIC_ORIGIN` when set.

## Reliability

- **C168 · minor · S** — `pushPrefToServer` (`public/prefs.ts`) logs a 429 (`prefsLimit`) or 413 (over the 2 MB cap) with the `[prefs]` tag but doesn't retry it until the next sign-in merge, so a pref change can stay local for the session. Re-schedule the key's push.
- **C169 · minor · M** — `.githooks/pre-commit:10` sets aside only tracked unstaged edits; an untracked file the commit lacks (a new module) still lets the checks pass. Set untracked files aside too, per worktree (not `git stash -u`, shared across worktrees).

Dependabot or Renovate could open them, since CI (`.github/workflows/ci.yml`) runs `check` and the e2e suite on PRs, but their PRs lack the `CHANGELOG.md` entry the pre-commit hook requires (CI doesn't check it) and skip `npm run build`, so each still needs a local pass through dependency-audit's Applying.
- **C190 · minor · M** — a shared `?f=` or compare link with many account sources fires all their `/api/common-games` calls at once (`resolveListWithSources`, `public/listResolve.ts:152`): past `SEARCH_RATE_LIMIT_MAX` they 429, the whole list fails, and the viewer's search budget is spent for a minute. - **C200 · minor · S** — an achievements rarity call refused by the client share (`server.js:1029`) only sets `rarityFailed`, so the panel shows the generic rarity failure, not the share message `achievementsRefusal` (`public/panelData.ts`) shows on a 429. - **C286 · minor · S** — inbound errors leave no history: `daily` (`lib/metrics.js`) persists outbound statuses only, so a burst of 5xx on a route vanishes at the next restart. Persist inbound status classes per day and route in `metrics_daily` too.
- **C287 · minor · M** — `daily` keeps no latency, so the day an upstream started slowing down before it erred can't be dated once `sinceRestart` resets. Persist a per-day latency bucket count per group and label, read as p50/p95.
- **C320 · minor · S** — a long Fanatical outage shows old pick-and-mix tier prices as current: `lastMap` (`lib/fanatical.js`) answers every failure, and `withCachedPickAndMix`, however long past its row's expiry. Stop serving it past a cap (e.g. twice the row's TTL), so tiers fall back to no price.
- **C321 · minor · S** — `achievementsLimit`'s skip (`server.js`) sees a cached schema, so the route's one-off forced schema refetch (a schema cached empty before the store page listed achievements) reaches Steam uncounted. Count the request when that refetch's condition holds.
- **C322 · minor · L** — which features are really used is invisible: nothing counts them. No appid, IP, UA or Steam ID (journeys.md's non-goals); no third-party analytics. Shares C283's beacon route; needs C270's privacy page first. A reviewed plan.
