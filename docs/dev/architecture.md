# Architecture

An Express backend (`server.js` + `lib/*`, plain CommonJS JavaScript but for `lib/streamEvent.mjs`) serving a Solid.js single-page app (`public/*`, TypeScript, bundled by Vite). The backend is a caching proxy over Steam/HLTB/IsThereAnyDeal/ProtonDB/Fanatical and the Xbox PC Game Pass catalog; accounts, lists and preferences live in the browser's `localStorage`, and the server stores them only for a signed-in user who syncs (`users`, `sessions`, `user_prefs` — [data.md](data.md)).

Setup and dev commands are in [README.md](../../README.md), the index of the other docs in [CLAUDE.md](../../CLAUDE.md#where-things-are-documented); tests and hooks in [testing.md](testing.md).

## Build and serving

- `npm run build` (`vite build`) bundles `public/`'s two HTML entries into `dist/` (gitignored): `index.html`, the SPA, and `present.html`, the presentation window's own page (served as a static file, none of the SPA in it). `server.js` serves `dist/` when `dist/index.html` exists, else `public/` raw — which browsers can't run (TypeScript), so a fresh clone needs a build before `npm start`.
- In dev, Vite (`npm run dev:frontend`, `root: 'public'`) serves the sources and proxies `/api` and `/auth/` (Steam sign-in, the browser's Host kept) to Express (`PORT`, `default.env`). Its port is pinned (`server.port`/`strictPort`): a different port is a different origin, so a fallback port would reset localStorage, cookies and sign-in.
- `publicDir: '../static'`: `static/` holds the files copied into `dist/` as-is (the link-preview image and the icons); `public/` is source, so it can't be Vite's default `publicDir`.
- **Behind the live reverse proxy** (Caddy): it gzips HTML, JS and JSON, and sets HSTS, `nosniff`, `X-Frame-Options: SAMEORIGIN` and `Referrer-Policy: same-origin` (checked 2026-10-31). `server.js` does neither, except the details stream's own gzip, so a bare `npm start` serves uncompressed.
- **SPA fallback**: routes are real paths (`/lists/owned`, `/game/440`), so `server.js` ends with a catch-all (`app.get(/^\/(?!api\/)(?!.*\.[a-zA-Z0-9]+$).*/)`) sending `index.html` after the API routes and static files, with Open Graph tags injected for chat link previews (crawlers don't run the SPA); `linkPreview` picks each page's card from the cache alone, never fetching: a game (`/game/<appid>`, or any list's `?game=`), a bundle (`findCachedBundle`, any region), Owned/Wishlist/Compare from cached Steam names (`peekSteamId`, `player:`), developer/publisher and a few fixed pages from the URL; anything else gets the site card. Vite's dev server does the fallback by itself, without the tags.

## Backend modules

- **`server.js`** — Express setup and route handlers only; all upstream work lives in `lib/*`.
- **`lib/config.js`** — loads `.env` over `default.env` and exports the TTLs, budgets, session lifetime and upstream pacing shared across modules.
- **`lib/db.js`** — opens `db.sqlite` and applies its append-only `MIGRATIONS` ([data.md](data.md)).
- **`lib/cache.js`** — persistent cache over `db.sqlite` (`getCached`, `setCache`, `isCached` for limiter skips, `getCacheEntryCounts` for health and metrics); `createCachedFetch` binds a module's dedup into its `cachedFetch(key, { force }, load)`, the cache-then-dedup skeleton of a single-key upstream getter.
- **`lib/dedup.js`** — `createDedup`: concurrent calls for the same key share one promise.
- **`lib/steam.js`** — Steam Web API and store calls (`resolveSteamId`, `getOwnedGames`, `getWishlist`, `getFriendList`, `getPlayerSummaries`, `getGameRating`, `getAppDetails`, `getStoreBrowseItem`, `prefetchStoreBrowseItems`, `resolveSteamTags`, `extractDemoAppid`, `searchStoreGames`, `getGameNews`, …), ProtonDB, and their per-host semaphores (`storeLimit`/`tagLimit`/`protonLimit`/`reviewsLimit`).
- **`lib/hltb.js`** — HLTB auth + search (`getHLTB`), behind its own semaphore (`hltbLimit`).
- **`lib/itad.js`** — IsThereAnyDeal calls (`getShopId`, `getBundles`, `resolveSteamAppIds`, prices) behind bundle browsing and every price column.
- **`lib/fanatical.js`** — Fanatical's storefront feed, for pick-and-mix tier prices ([bundles-and-prices.md](bundles-and-prices.md#fanatical--pick--mix-tier-prices)).
- **`lib/humbleChoice.js`** — Humble Choice's end date from Humble's schedule, over ITAD's early one ([bundles-and-prices.md](bundles-and-prices.md#humble-choice--end-date)).
- **`lib/itadDates.js`** — `overrideExpiry`: a better source's end date over ITAD's, tallying whether ITAD's agrees for `GET /api/metrics`' alerts.
- **`lib/earlyExpired.js`** — `findEarlyExpired`: bundles still on sale that ITAD already expired, from its expired pages ([bundles-and-prices.md](bundles-and-prices.md#fanatical--pick--mix-tier-prices)).
- **`lib/gamepass.js`** — the PC Game Pass catalog as Steam appids ([bundles-and-prices.md](bundles-and-prices.md#xbox-pc-game-pass--catalog-feed)).
- **`lib/streamEvent.mjs`** — one game's details-stream event, without screenshots and trailers; an ES module so `e2e/mockApi.ts` shares it.
- **`lib/upstream.js`** — `createSemaphore` (concurrency cap + per-slot pacing, registered for `GET /api/metrics`) and `upstreamError`, shared by the upstream clients.
- **`lib/circuitBreaker.js`** — one 403-storm breaker per blocking-prone upstream (Steam store, HLTB, ProtonDB).
- **`lib/metrics.js`** — `createTrackedFetch`, outbound budgets and the counters behind `GET /api/metrics` ([observability.md](observability.md)).
- **`lib/auth.js`** — Steam OpenID 2.0 sign-in (each assertion accepted once per process run, within 5 minutes of its nonce), cookie sessions (sliding, renewed by `GET /api/me`) and per-key user prefs, behind `/auth/*` and `/api/me*`.

The dedup map, semaphores, breakers and metrics are process-local: correct for the single-process deployment, but several instances would each get their own and multiply upstream traffic silently.

## Tooling

- **`tsconfig.json`** — `strict`, `noUnusedLocals` (dead imports fail the typecheck), `noEmit`, `moduleResolution: bundler`, `verbatimModuleSyntax` (type-only imports use `import type`), over `public/**/*.ts`; `paths: {"/*": ["./public/*"]}` maps the browser-style absolute imports (`'/utils.ts'`) onto the source tree. `tsconfig.e2e.json` extends it over `e2e/`. The compiler is TypeScript 7 (`tsgo`).
- **`eslint.config.mjs`** — `eslint-plugin-solid`'s `flat/typescript` rules, plus `no-restricted-imports` banning `lucide-solid`'s barrel imports ([frontend.md](frontend.md#icons)), parsed by `@babel/eslint-parser` ([decisions.md](decisions.md#linting-babel-not-typescript-eslint)). `solid/reactivity` is the rule that matters ([frontend.md](frontend.md#reactivity)). `.mjs` because `package.json` has no `"type": "module"`.
- **Prettier** (`.prettierrc.json`) formats the whole tree.

## API routes

| Route                                                                    | Purpose                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/common-games`                                                 | Resolve identifiers, fetch + union owned libraries per slot, group by owner set                                                                                                                                                                                                                            |
| `POST /api/wishlist`                                                     | One account's (or Family's) wishlist                                                                                                                                                                                                                                                                       |
| `POST /api/friends`                                                      | One account's (or Family's) union of friends, cross-referenceable against another account's own friends client-side                                                                                                                                                                                        |
| `GET /api/game-details/:appid`                                           | Rating, HLTB, store metadata, tags, ProtonDB for one game                                                                                                                                                                                                                                                  |
| `GET /api/game-meta/:appid`                                              | Store metadata alone for one game (the panel's DLC card, an opened list row's media)                                                                                                                                                                                                                       |
| `POST /api/game-details/stream`                                          | The same, for a list of appids, streamed over SSE: a game cached throughout as one event, any other as a fast part (`fetchFastDetails`: rating, HLTB, tags, ProtonDB, basics) and a store part behind it (`fetchStoreDetails`: appdetails, under Steam's store details cap), each from its own worker pool |
| `GET /api/game-news/:appid`                                              | That game's own Steam announcements                                                                                                                                                                                                                                                                        |
| `GET /api/achievements/:appid`                                           | Achievement list + per-account progress                                                                                                                                                                                                                                                                    |
| `GET /api/search-games`                                                  | Store search by name                                                                                                                                                                                                                                                                                       |
| `GET /api/creator-games`                                                 | A developer's or publisher's games (`role`, exact `name`; `refresh=1` forces), with `total` and `capped`                                                                                                                                                                                                   |
| `GET /api/game-pass`                                                     | The Steam games in PC Game Pass for `country`'s catalog, the others by name (`refresh=1` forces)                                                                                                                                                                                                           |
| `GET /api/bundles`, `GET /api/bundles/:id`, `POST /api/bundles/resolve`  | ITAD bundle listing/lookup, ITAD gid → Steam appid                                                                                                                                                                                                                                                         |
| `POST /api/prices`                                                       | ITAD prices for a batch of gids or appids                                                                                                                                                                                                                                                                  |
| `GET /api/game-bundles/:appid`                                           | ITAD: the current bundles one game is in (the side panel's Price card)                                                                                                                                                                                                                                     |
| `GET /api/health`, `GET /api/metrics`                                    | Config/liveness and the running build (`version`, `commit` read at startup, `since`), and the counters in [observability.md](observability.md)                                                                                                                                                             |
| `GET /auth/steam/login`, `GET /auth/steam/callback`, `POST /auth/logout` | Steam OpenID sign-in/out (`lib/auth.js`) — see [lists-and-accounts.md](lists-and-accounts.md)                                                                                                                                                                                                              |
| `GET /api/me`                                                            | The signed-in user's steamid and every prefs key as `{ value, updatedAt }`, or `{ steamid: null, prefs: null }` signed out — always 200 (`initAuth` calls it on every page load)                                                                                                                           |
| `PUT /api/me/prefs/:key`                                                 | Writes one prefs key (`{ value, updatedAt }`), so concurrent writes to different keys can't clobber each other; a write always overwrites. 400 for a key the frontend never syncs (`isSyncedPrefKey`, `lib/auth.js`), 413 past 2 MB per account (`PREFS_MAX_BYTES`), 401 without a valid session cookie    |

Rate limits ([observability.md](observability.md), [data.md](data.md)):

- Every route that can reach an upstream, plus the auth routes and the prefs write, is behind a named `express-rate-limit` instance.
- Most `skip` requests they can answer from cache. Always counting: `bundlesById` (a looser budget instead), `auth` (a fixed `max: 20` in `server.js`, login and callback), `prefs` (apart from `auth`), and the stream route (its array body defeats `details`' per-appid skip).
- `BUNDLES_RATE_LIMIT_MAX` backs six limiters — `bundlesListLimit`, `bundlesByIdLimit`, `bundlesResolveLimit`, `pricesLimit`, `gameBundlesLimit`, `gamePassLimit` — each `skip`ping a request it can answer from cache by checking the cache keys that route reads (the same pattern as `detailsLimit`); `bundlesListLimit` checks only the page it serves, not the expired pages `findEarlyExpired` may walk. Without the skip, reloading a bundle page a few times would 429 a genuinely new bundle open.
  - `pricesLimit` checks `itad-price:` for whichever of `gids`/`appids` was sent, plus `itad-gid:` for `appids`.
  - `bundlesByIdLimit` can't skip — `findBundleById` walks a variable number of pages — so it gets twice the budget instead; its pages are still cached underneath.
- A middleware after the JSON body parser runs each request under its client's key (`clientKey`, the limiters' key) in an `AsyncLocalStorage`, so the outbound calls it makes are charged to that client's share of the outbound budgets ([observability.md](observability.md#outbound-budgets)).
- No limiter: health, metrics, `GET /api/me`, logout, `/opensearch.xml` and the SPA shell (cache-only, no upstream call).

Inputs (`server.js`) — each lands in a cache key, so only what the frontend sends is accepted:

- `members` (and `/api/achievements`' `steamids`): a Steam64 id, a custom-URL name or a `steamcommunity.com/id|profiles/…` URL holding one (`isSteamIdentifier`); anything else is a 400.
- `gids`: ITAD game ids (UUIDs); anything else is a 400.
- `country`: one of `public/regions.json`'s codes (the region picker's list), else US.
- `/api/bundles`: `sort` is always `-publish`; `offset` and `limit` are integers, `limit` clamped, and an `offset` past `MAX_BUNDLES_OFFSET` gets an empty page, which ends Load more.

## Request flow

1. Frontend POSTs `{ members: ["alice", "bob_family"] }` to `/api/common-games`: one account, or a Steam Family's member accounts, whose libraries are unioned. A comparison makes one call per player and combines them in the browser.
2. Server resolves every identifier to a Steam64 ID, deduplicates, fetches all libraries in one parallel pass, unions them, and returns `{ games, players, playtime, lastPlayed, recentPlaytime, fetchedAt }`:
   - `players[]` carry each account's `gameCount`, shown next to it without a second request.
   - A private library fails the call with a 400 naming every such member, plus `accounts: [{ steamid, name }]` for the UI to name the player and link Steam's privacy settings; an upstream failure on another member wins over it (502).
   - `playtime`/`lastPlayed`/`recentPlaytime` are keyed by appid then by the member who owns it; `recentPlaytime` is Steam's two-week playtime, left out for an account whose cached library is older than that window.
3. The frontend renders rows at once, then POSTs the appids to `POST /api/game-details/stream` (SSE) for rating, HLTB, store metadata and tags over one connection. It leaves out screenshots and trailers: an opened game loads its own from `GET /api/game-meta` ([frontend.md](frontend.md#rows-streaming-and-stale-loads)).
4. The stream route works the list through a bounded worker pool (`STREAM_CONCURRENCY`) pulling from a shared cursor, fully cached games first (behind uncached ones they'd wait on the upstreams' pace), checking the client is still connected before each appid — dispatching every appid up front would make that check unreachable and let one request fill the shared semaphore queues ahead of everyone else's. It's gzipped when accepted (~3.2 KB per game, 570 B gzipped, on a warm load) and flushed once per event-loop turn. A client past `STREAM_MAX_PER_IP` open streams gets a 429, so parallel streams can't fill the shared store queue.
